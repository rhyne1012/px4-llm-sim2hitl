# v2.1.0 — trims and linear models; a fast core for real aircraft; safer deploys

**In short.** A vehicle repository can now get its aircraft's trims, linear models and transfer functions in one command (for gain tuning, an anchor check, or a paper), and a fast core for training that also works for an aircraft other than the test vehicle. Writing to a flight controller is safer: recipes and boards have roles, a reboot must be proven, and a flight that lost simulator timing no longer passes. JSBSim is unchanged; PX4 carries only the small patches listed in `px4/lock.toml`.

**Upstream versions.** PX4 v1.18.0 (`935addf`) with the patches of `px4/lock.toml` (a Cube Orange+ HIL board variant; one SITL sensor fix), JSBSim 1.3.3 unmodified.

## Upgrading from v2.0.0: what a vehicle repository must change

- **Roles.** Every recipe's `params.json` states `"role"`: `hitl`, `bench` or `flight` (`docs/recipes.md`, Roles). Every flight controller needs a role from a person once: `tools/fc.py --link <FC> board-role --role hitl|aircraft`. A flight recipe is deployed only with `--flight`.
- `tools/fly.py sitl` needs `--instance` (each task owns its SITL FC instance numbers); a run starts the instance from a fresh state unless `--keep-state`.
- `tools/hitl_flight.py`, `sitl_flight.py`, `fc_log.py` and `fc_params.py` are removed: use `tools/fly.py`.
- `tools/deploy.py --reuse` reuses a flight controller only with the board record of its last flash: the first HITL after upgrading needs `--deploy flash`.
- Recipe files are no longer changed by a flash: drop `"flashed"` (and `build.log`) from `firmware.json`. `tools/px4build.py --if-needed` now also compares the make target, PX4 commit and committer, so every recipe is built once more.
- The SITL FC applies the toolkit's own SITL patches first (`px4/patches/sitl/`): a vehicle repository that lists the IMU first-sample patch in `sim2hitl.lock` `sitl_build` must drop it. SITL FC builds move to a folder per repository and recipe, so each is built once more.
- Moving a flight controller from another recipe or vehicle: `--reset-unmanaged` now also restores the recipe's airframe and boot values the earlier recipe changed. A HITL recipe states `GPS_1_CONFIG` 0 in `boot` (PX4 sets it at every HITL boot), and a recipe states its board's script defaults in `boot` (`docs/recipes.md`).
- A recipe that does not state `SYS_HITL` expects PX4's default 0: leaving HITL always needs `--allow-hitl-change`.
- The fast core's outputs gained the external-force columns and its state four auxiliary entries; code that reads them by name (the layout file) is unaffected.

## New

- `tools/linear.py`: level, turning and sideslipping trims (also where JSBSim's FGTrim fails, e.g. with fast electric motors), linear models, modes, actuator and engine poles, transfer functions with and without the servo, each checked against the nonlinear model; `--compare` of two such records (an anchor's behaviour check), which needs converged trims, the same checks, inputs and output map; `tools/linear_model.m` reads them into MATLAB.
- Fast core: 3D tables, `fcs_function`, external forces, an electric engine with a direct thruster; its checks and benchmark work for any fixed-wing vehicle.
- A recipe patch may be one of the toolkit's (`toolkit:px4/patches/<file>`), so a vehicle repository need not copy the Cube HIL board patch.
- `SIM2HITL_SITL_BUILD_TREE` for the SITL FC's build tree.
- `AGENTS.md`: the general working rules for every vehicle repository; report the plain picture first.

## Fixed

- A refused reboot was counted as a reboot; now a reboot needs evidence. `tools/fly.py hitl --deploy none` flew without checking the recipe; now deploy's read-only plan must pass. `tools/fc.py params-restore` could restore another board's parameters or change `SYS_HITL`; now it refuses without the person's flag.
- A flight passed although simhost lost lockstep (SITL) or ran late (HITL); now it fails.
- After a reboot the FC was asked for its identity three times in 6 s; once, right after a HITL flight, a Cube Orange+ took longer and the run failed in its recover. Now it is asked for up to 20 s, and the reboot proof uses PX4's TIMESYNC time since boot (a Cube in HITL denies SYSTEM_TIME).
- After a failed SITL FC start, an earlier log was checked as the run's own.
- Testbird's HITL firmware could not be built by `tools/px4build.py`; Testbird's recipe now passes its deploy.

## Verified
