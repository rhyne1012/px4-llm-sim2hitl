# v2.1.0 — trims and linear models; a fast core for real aircraft

**In short.** A vehicle repository can now get its aircraft's trims, linear models and transfer functions in one command (for gain tuning, an anchor check, or a paper), and a fast core for training that also works for an aircraft other than the test vehicle. Flights are run more safely: each run proves which firmware it flew and uses only its own SITL instance. PX4 and JSBSim are unchanged.

**Upstream versions.** PX4 v1.18.0 (`935addf`), JSBSim 1.3.3, both unmodified.

## Upgrading from v2.0.0: what a vehicle repository must change

- `tools/fly.py sitl` needs `--instance` (each task owns its SITL FC instance numbers); a run starts the instance from a fresh state unless `--keep-state`.
- `tools/hitl_flight.py`, `sitl_flight.py`, `fc_log.py` and `fc_params.py` are removed: use `tools/fly.py`.
- `tools/deploy.py --reuse` reuses a flight controller only with a record of the image flashed on that board: the first HITL after upgrading needs `--deploy flash`.
- The SITL FC applies the toolkit's own SITL patches first (`px4/patches/sitl/`, now the IMU first-sample fix every vehicle needs with simhost): a vehicle repository that lists that patch in `sim2hitl.lock` `sitl_build` must drop it (a patch given twice is refused). The SITL FC's PX4 hash changes, so it is built again.
- Moving a flight controller from another recipe or vehicle: `tools/deploy.py --reset-unmanaged` (also `tools/fly.py hitl --reset-unmanaged`) now also restores the recipe's airframe values the earlier recipe changed. A HITL recipe states `GPS_1_CONFIG` 0 in `boot` (PX4 sets it at every HITL boot; `docs/recipes.md`).
- The fast core's outputs gained the external-force columns and its state four auxiliary entries; code that reads them by name (the layout file) is unaffected, code with fixed indices must be updated.

## New

- `tools/linear.py`: level, turning and sideslipping trims (also where JSBSim's FGTrim fails, e.g. with fast electric motors), linear models, modes, actuator and engine poles, transfer functions with and without the servo, each checked against the nonlinear model; `--compare` of two such records (an anchor's behaviour check); `tools/linear_model.m` reads them into MATLAB.
- Fast core: 3D tables, `fcs_function`, external forces, an electric engine with a direct thruster; its checks and benchmark work for any fixed-wing vehicle.
- `AGENTS.md`: the general working rules for every vehicle repository; report the plain picture first.

## Verified

`docs/verification.md`: Testbird in HITL on a Cube Orange+ through `tools/fly.py`; Testbird's trims, linear models and fast core; a private vehicle repository's aircraft: its fast core against JSBSim (to rounding; 11–13× JSBSim's speed on one thread), its three task recipes in SITL with these tools, and the firmware build of its recipes.

## Assets

A backup of the JSBSim files this version uses, in case the upstream ones disappear: the source archive and the Python wheel named in `jsbsim/lock.toml`, with their SHA-256 there.
