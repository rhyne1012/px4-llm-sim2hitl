# px4-llm-sim2hitl

**繁體中文**（英文版之後補）

讓你和你的 AI，把一架飛機從模擬一路帶到實體飛控 HITL 的**膠水層**。

> 狀態：v2 草稿，還在開發。舊版（Simulink → C → HITL，範例飛機 SkySurfer）封存在 tag `v1-final`、分支 `legacy-v1`。

## 理念

**站在巨人肩上。** 飛控用 [PX4](https://px4.io)，飛機物理用 [JSBSim](https://github.com/JSBSim-Team/jsbsim)。兩者都原封不動、鎖定版本，就像大家用 PX4 開發飛控一樣用 JSBSim 做飛機。

**這裡是膠水，只做巨人之間沒人做的事。**

- 膠水該強的：
  - HITL 的即時節拍與實機安全
  - 一條龍部署
  - SITL 與 HITL 用同一把尺
  - 給 AI 的交接
- 膠水該薄的：物理和飛控本身。自己再寫一份，就是和巨人重複，變成債。

**不放真的飛機。** 每架飛機一個 repo，鎖定這裡的版本來用。這裡只有測試載具，給膠水自己測試。

**是交接，不是自動化。** AI 每開一次新對話，都像第一天上班的新同事。這裡寫給它的是：

- 這條路怎麼走
- 哪裡有坑
- 哪些已經驗證過
- 哪些事要問人

工具是理解的副產品：同一件事做了兩三次，才把它固定成指令。

**結論和證據一樣大。** 每個結論都要說得出：

- 依據：哪次測試、哪份紀錄
- 範圍：版本、配方、飛控、模式

證據少，就把話說小。

**AI 處理技術，人決定方向。** 目標、選擇、成功條件問人；其餘由 AI 查、AI 做，用白話回報。

## 三層

```
  PX4（飛控）      JSBSim（飛機物理）      ← 巨人：鎖定版本，不改
          ╲          ╱
     px4-llm-sim2hitl（膠水）             ← 這裡
              │  鎖定版本使用
     你的飛機 repo（飛機、任務、紀錄）     ← 例如 SkySurfer
```

## 膠水提供什麼

- **模擬主機**：JSBSim 加上航電（感測器、舵機訊號鏈），用 PX4 的標準 HIL 訊息溝通。接電腦上的 PX4 就是 SITL，接飛控就是 HITL，是同一支程式。
- **一條龍部署**：編譯 → 燒錄 → 身分核對 → 參數 → 開機檔 → 試飛 → 飛控紀錄，一個指令跑完。
- **同一把尺**：一份測試案例（情境、判定、紀錄）可以跑四層。每一層證明不同的事：
  - 只有演算法
  - 電腦上的 PX4
  - 實體飛控
  - 實飛
- **實機安全**：身分核對、未解鎖、參數讀回、恢復。這些不可繞過。
- **本機資源鎖**：好幾個飛機 repo 共用同一台電腦時，飛控、SITL 編號、PX4 原始碼樹不會互相踩到。
- **錨點工具**：記下飛機的行為答案並上鎖，人同意才升版。
- **新飛機產生器**與**測試載具**（一台固定翼、一台四軸）。

## 怎麼開始

把這個網址貼給你的 AI，說你想做什麼。

- **新飛機**：請它用產生器開一個飛機 repo，先用測試載具走通 SITL → HITL。
- **已有飛機 repo**：在那個 repo 裡開發就好，平常不用碰這裡。
